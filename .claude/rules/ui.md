# Rules — components, styles, formatters and the Mining tab

Read first, for what you touch: `docs/claude/ui.md`, `docs/claude/screens.md`.

| Constraint | Rule |
|---|---|
| Every masked field goes through `ui/PassphraseInput` | Never hand-roll an `<input type="password">`. The shared widget bakes in the four iOS suppressions (an autocapitalized passphrase never decrypts) and the `onPointerDown`+`preventDefault` focus guard (an onClick-only toggle blurs the field and collapses the iOS keyboard mid-entry). A `grep -rn 'type="password"' src` must return ONLY `AppUnlockGate.tsx` + `StoreMigrationGate.tsx` — both unrendered, retained as the Option-3a rebuild basis. PINs use it too, passing `inputMode="numeric"` so the keypad survives reveal |
| `SummaryBar fmtUSD` | Local sign-preserving — NEVER replace with shared version |
| Mining electricity | Fiat overhead — 100% sats kept, never deducted |
| Mining strategy cards | Fixed presets — independent of per-device `soloMining` |
| `MiningOddsBar` | Reads store directly — not props |
| `fmtMining` | Inlined in `format.ts` — no circular import |
| Override a composed class's property on a DOUBLED selector, never beside `composes:` | A declaration in the composing rule ties the composed class's specificity (0,1,0), so the bundle's rule order decides, and that order is an accident of the import graph that differs between dev and production. P10 shipped Mining, Power Law and the Converter 600px wide in production while dev looked right. Put the override on `.x.x` (0,2,0), which wins in any order: `.main.main { max-width }`, `.chartBox.chartBox { height }`. Every single-class rule of the composing class counts, a media query's included, and so do shorthands (`border` covers `border-color`). `composedOverrides.test.ts` IS the audit, over every `*.module.css` under `src/` (P9–P11) |
| Never `position: fixed` under EdgeBackGesture's `.page`, and never a body `scroll-padding` | `.page` has `will-change: transform`, which makes it the containing block for its fixed descendants: a fixed element there scrolls away with the page (measured on the control dock, F2). Pin to the window's edge with `position: sticky` as the face's LAST child — `ControlDock` does, on all four engine faces (Decision, Cycling, Ownership — after its two-column `.shell`, F16 — and Strategy), and it also moves with the page through a swipe-back. In full mode a sticky element needs an ancestor that is no scroll container: `[data-active-tab="almanac"] .main` (Δ1). A body `scroll-padding-bottom` kept scrolled-to elements above the dock, but focusing the dock itself then jumped the page by ~400 px (F5). Pinned by `controlDockWiring.test.ts` (PREMISE, STICKY-CSS, ONE-DOCK, DOUBLED; on the parents P-ONE-DOCK and P-DOUBLED) and `e2e/controlDock.spec.ts`. Four Settings overlays already sit under `.page` (NostrAuthGate, ViewerLoginFlow, RecoveryKeyCeremony, RestoreBackupFlow — each `position: fixed`, rendered inline by SettingsMain in simple mode) — logged; not fixed in this run |
| `NumberInput` suffix | Avoid inside input — cursor issues; use external label |
| `NumberInput` saving | Every field declares how it saves — `save` is required. `'button'` for a figure read off Strike or Coinbase (the four dated setters `setCbLoanBalance`, `setCbLiquidationPrice`, `setAdvisorActualBlocBalance`, `setColdStorageBtc`; `setCbCollateralBtc`; `emitBalanceReading`): saved once by "Save — dated today" or Enter. `'leave'` for a plan setting (a field of the synced plan, or the manual BTC price): saved once on leaving or Enter — and what was typed is saved when the app goes away with it focused, the edit going on (F-2d-1). `'live'` only for a draft, a what-if or a read-only field. Leaving, Enter and Save go through ONE rule, `numberCommit` (`ui/numberInputModel.ts`, BL34–BL35): nothing unless typed, never the figure the field shows (a `'button'` field's re-entry aside — its save dates it). Never call `onChange` from `onBlur` or `onKeyDown` directly, and never make a plan or dated field `'live'`: a click in and out re-dated a dated figure (F-2c-1), writers that do more than save fired on a mere click, and typing saved every partial — a journal reading per keystroke on Coinbase's collateral. Pinned by `numberInputModel.test.ts` (WIRING, SITES) and `e2e/numberField.spec.ts` |
| A page closed from code blurs the focused field first | React runs no `onBlur` for a field it unmounts (react-dom 18 turns its events off for the commit), and a touch swipe — or a click dispatched from code — moves no focus: a typed `'leave'` field, or the goal field, would go unsaved (F1, BL34–BL35; measured with a real touch swipe). `EdgeBackGesture` blurs before a committed swipe's `onBack()` and before its forwarded tap's click. Pinned by `numberInputModel.test.ts` (GESTURE) and `e2e/numberFieldSwipe.spec.ts` |
| A field that saves on leaving also saves what was typed when the app goes away — without ending the edit | Going away runs no React `onBlur` on iOS — React listens for `focusout`, and WebKit's loss of page focus sends a bare `blur` — and iOS may then close the app: a typed plan setting was lost on the owner's iPhone (F-2d-1, build 2e). `NumberInput` saves a focused `'leave'` field on the window's `blur` or `visibilitychange` → hidden, by `numberCommit` (`awaySaves`), and leaves its text and `typed` alone — rewriting the text there put an emptied field's old figure back under the caret ($40,004,200 saved for 4,200 typed, measured). A new editor that saves only on leaving needs the same; the goal field and `SliderInput`'s edit box don't have it yet (older, logged). Pinned by `numberInputModel.test.ts` (AWAY) and `e2e/numberFieldAway.spec.ts` |
| Tab hidden guard | `useEffect` in `AppShell` redirects when the active tab is hidden — or, since the plan of record's Run 4, is the CB Loan or Emergency tab with the Coinbase loan off. Full mode only — the one mode with a tab bar (BL47): in simple mode every tab but Settings and the Almanac opens the journal, so it redirects nothing there, and it re-runs on a switch of mode |
| `SettingsMain` ALL_TABS | Keep in sync with `AppShell` `ALL_TABS_META` |
| The venue colours: every venue mark reads a venue token, and a stored colour shows only if THE rule passes it (BL15) | Every mark that stands for a venue — its dots, bar segments, chart lines and the limits drawn in its colour, its venue words and figures, the cold totals, the rows of the charts' shared hover box — reads `--venue-strike`, `--venue-coinbase` or `--venue-cold` (`tokens.css`; they default to `--text-primary`, `--coinbase` and `--btc`), never those three directly: `var(--coinbase)` is read by `tokens.css` alone. What keeps its own colour: the bitcoin orange where it means bitcoin itself (Yours, BTC gained, ₿), the Cycling face's lone CB LTV line and its limit, the "Debt shifted" tile (the defense's accent — debt moved from Coinbase to Strike, a mark for neither venue), the calendar's "CB collateral" dot (bitcoin going in) and the hidden CB Loan tab's comparison columns. Every venue mark sits on `--bg-app`, `--bg-card`, `--surface` or `--surface-2` — the rule's four, the shared hover box (`CyclingFace.module.css` `.tooltip`) included; Coinbase's blue reads 2.7:1 on `--surface-3`. The colours are a pref (`venueColors` on `prefs:v1`) whose undefined never travels; a stored colour reaches CSS only through `applyVenueColors` (`useVenueColors`, AppShell's first statement), and only if THE rule (`checkVenueColor`, `lib/venueColors`) passes it; the setter (`setVenueColor`) runs the same rule, starts from the colours the rule lets show, and writes nothing for the colour a venue already wears. Pinned by `venueColorsWiring.test.ts` (TOKENS ONLY, STAYS, SURFACES, ONE PAGE, SINK, PICKER), `venueColors.test.ts` (RESOLVE, SINK) and `venueColorsStore.test.ts` (NEVER, HIDDEN, UNCHANGED) |
| The Almanac's faces: ONE catalogue, the grid (BL45), a list on a computer (BL46's A) | Which faces the hub offers, in which group and order, is `almanacGrid.ts` alone (`FACE_TILES`, `faceShown`, `gridGroups` — pure: no store, no env). The hub reads its four gates once (`hasCbLoan`, `ledgerFaceAvailable`, `FIRE_ON_THIS_DEPLOY` and the lens, `useSeenAsViewer()` — a viewer's device or the owner's trusted preview, BL50: BL48's row below) and passes them in — no gate of its own; one fallback effect returns an open face whose gate closes to the grid. For the owner the grid offers exactly the faces the pill row did (BL45's kill criterion); a trusted viewer's, those less the owner's-only — FIRE (`ownerOnly`, BL48 — the row below). A new face needs its tile, its `renderFace` branch above the Converter fallback (C8) and its `FaceIcon` drawing. Back is one level: on any face the header's "Almanac" goes to the grid (full mode: the eyebrow's), with nothing between the header and the page (2026-10-31); Branch I's edge swipe chains through `registerBack`, except for a face the plan's link opened, which swipes straight out; the header's "←" always leaves, named for the page it opens (BL47 — the row below). From 1200px (`ALMANAC_LIST`) the same groups are a list beside the open face — no grid page, so no step back: the header's "Almanac" is plain and the swipe leaves; a face is always open there (`firstListFace`: the one asked for, else the face last open this session while the list shows it, else Decision — in memory only, one memory per lens: the owner's own list never opens on his preview's face, nor the preview's on his, BL50). 1200 is where every face keeps its own width beside the list in either mode (the plan faces' control bar wraps narrower — measured): a wider list, or a face wider than 960px, moves it (WIDTH). Both sides of 1200 are one tree, so crossing it never remounts the open face. Pinned by `almanacGrid.test.ts` (CATALOGUE, ORDER, GATES, PILLS, GROUPS, GRID, ONE RULE, BACK, TITLE, BADGE, SHELL, ICONS, WIDTH, FIRST, LIST, KEEP, OWNER ONLY, NOTE, WHAT-IF), `e2e/almanacGrid.spec.ts` and `e2e/almanacList.spec.ts` |
| The simple-mode header's way out says where it goes, and never goes nowhere (BL47) | Branches H and I's "←" (Settings, the Almanac) reads `backPlace(to, { viewerMode, viewerPreview, simpleView })` (`Layout/backPlace.ts` — pure): the name of the page that tab opens, in AppShell's own order — "Almanac" (Branch I), a viewer's "Home" (Branch G), the owner's "Preview" (Branch J's preview), else "Dashboard" or "Journal" by `simpleView` (Daily and Monthly are both the Journal) — never a bare "← Back". A new simple-mode branch, or a new page that opens Settings or the Almanac, updates the rule with its ORDER pin. Pinned by `backPlace.test.ts` (NAMES, VIEWER, PREVIEW, ALMANAC, EXIT, WIRED, EXIT WIRED, ORDER, GUARD) and `e2e/backPlace.spec.ts` (DASH, JOURNAL, MONTH, NOWHERE, HIDDEN) |
| Trusted viewers in the Almanac (BL48 — BL40's second piece), and the owner's trusted preview of it (BL50) | The Almanac opens for the owner and a TRUSTED viewer only: `Layout/viewerAccess.ts` (pure) — `viewerTier` (trusted or safe by the last snapshot applied, none before one) and `almanacOpensFor`, which AppShell reads once. A trusted viewer's way in is his home bar's "Almanac" (`ViewerHomeView`'s `onOpenAlmanac`, passed only then — the edge-back under-layer too). For any viewer, Settings and the Almanac are simple mode's pages (Branches H and I take `viewerMode` as well as `simpleMode`) — never the full-mode shell, whatever the owner's synced layout; the hidden-tab guard is the owner's full mode's alone (`if (simpleMode || viewerMode || …)`), so the owner's hidden tabs never bounce a viewer's Almanac. A loaded viewer the Almanac doesn't open for (safe, or demoted) gets his home on the Almanac tab (Branch G) — one still waiting has the waiting gate first (in production; the dev server skips the gates) — and an effect puts `activeTab` and `previousTab` back to 'living'. Inside the hub a viewer's shared inputs unlock — `ViewerWhatIf` (true) around the open face, since every control on a face there is a session overlay or the viewer's own tool (Mining) — and FIRE's face puts the lock back (false: its inputs save, and no viewer gets it). Everywhere else the lock stands: SliderInput, NumberInput and Toggle ask `useViewerLocked()` and read `viewerMode` no other way. A viewer gets no copies off the app (the schedule's Copy, Download and Print; the Ledger's CSV) and no Scenario Pin (it saves). The hub's viewer gates — FIRE's tile, the what-if note, Scenario's Pin row (its drift line and words too), the copies, the Ledger's Mining column — read the lens, `useSeenAsViewer()` (`Almanac/seenAsViewer.ts`, BL50): a viewer's device, or the owner's trusted preview — AppShell's one `PreviewAsViewer` provider, true around Branch I's hub while `previewTier` (`viewerAccess.ts`, pure) is 'trusted', false everywhere else (full mode has no preview) — so the preview's hub reads as his trusted viewer's, and his own Almanac as before. A face's data and its own lock still read `viewerMode` (GATES lists every reader). A new face control that SAVES locks for a viewer itself, or its face provides the lock back, and sits where the lens closes it (the preview runs on the owner's device, where no lock that reads `viewerMode` holds) — and the hub's faces may call only the store functions `viewerAlmanacWiring.test.ts`'s WRITES lists (two reads; the viewer's own tools, each named only in its tool's files — one, or two for `setBtcPrice`, `setMiningDevice` and `setMiningInputs`; three writes no viewer reaches, each named only in its own file — CALL SITES): a face that names a new one fails it until it is decided, and WAYS IN fails on the ways in it can read that would hide a write from WRITES — a store module imported for anything but the hook or a type, `useStore` written other than `useStore(` or `useStore.getState().name`, `getState()` not followed by a name, an inline arrow selector that returns or indexes its state. Both read the source as text, comments stripped, through the imports written as quoted relative paths: a selector in another shape (a spread, a function, a named or block-bodied one), a name built in a string, a store module reached another way (a bare `import './x'`, a backtick or absolute path) or code the comment stripper swallows gets past both — a new face's store access is still the review's to read.

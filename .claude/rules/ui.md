# Rules — components, styles, formatters and the Mining tab

Read first, for what you touch: `docs/claude/ui.md`, `docs/claude/screens.md`.

Each rule's full text — its mechanism, measures and history — is in `docs/claude/rules-in-full.md` § `ui.md`.

| Constraint | Rule |
|---|---|
| Every masked field goes through `ui/PassphraseInput` | Never hand-roll an `<input type="password">`: a grep of `src` for `'password'` or `"password"` finds `PassphraseInput.tsx` alone — since Sweep 2c moved the sign-in's recovery-key paste field onto it. The widget keeps the four iOS suppressions and its toggle's `onPointerDown`+`preventDefault` focus guard. PINs use it too, passing `inputMode="numeric"` |
| `SummaryBar fmtUSD` | Local sign-preserving — NEVER replace with shared version |
| Mining electricity | Fiat overhead — 100% sats kept, never deducted |
| Mining strategy cards | Fixed presets — independent of per-device `soloMining` |
| `MiningOddsBar` | Reads store directly — not props |
| `fmtMining` | Inlined in `format.ts` — no circular import |
| Override a composed class's property on a DOUBLED selector, never beside `composes:` | Put the override on `.x.x` (0,2,0). Every single-class rule of the composing class counts, a media query's included, and so do shorthands (`border` covers `border-color`). Pinned by `composedOverrides.test.ts` |
| Never `position: fixed` under EdgeBackGesture's `.page`, and never a body `scroll-padding` | Pin to the window's edge with `position: sticky` as the face's LAST child, as `ControlDock` is on the four engine faces (Decision, Cycling, Ownership — after its two-column `.shell` — and Strategy) and FIRE. In full mode a sticky element needs an ancestor that is no scroll container: `[data-active-tab="almanac"] .main`. Known, logged violations: the Settings overlays NostrAuthGate, ViewerLoginFlow, RecoveryKeyCeremony and RestoreBackupFlow, in simple mode. Pinned by `controlDockWiring.test.ts` (PREMISE, STICKY-CSS, ONE-DOCK, DOUBLED, P-ONE-DOCK, P-DOUBLED), `e2e/controlDock.spec.ts`, `fireWiring.test.ts` (DOCK LAST) |
| `NumberInput` suffix | Avoid inside input — cursor issues; use external label |
| `NumberInput` saving | Every field declares how it saves — `save` is required. `'button'` for a figure read off Strike or Coinbase (the four dated setters `setCbLoanBalance`, `setCbLiquidationPrice`, `setAdvisorActualBlocBalance`, `setColdStorageBtc`; `setCbCollateralBtc`; `emitBalanceReading`): saved once, by "Save — dated today" or Enter. `'leave'` for a plan setting (a field of the synced plan, or the manual BTC price): saved once, on leaving or Enter — and what was typed is saved when the app goes away with it focused, the edit going on. `'live'` only for a draft, a what-if or a read-only field. Leaving, Enter and Save go through ONE rule, `numberCommit` (`ui/numberInputModel.ts`): nothing unless typed, never the figure the field shows (a `'button'` field's re-entry aside — its save dates it). Never call `onChange` from `onBlur` or `onKeyDown` directly; never make a plan or dated field `'live'`. Pinned by `numberInputModel.test.ts` (WIRING, SITES), `e2e/numberField.spec.ts` |
| A page closed from code blurs the focused field first | `EdgeBackGesture` blurs before a committed swipe's `onBack()` and before its forwarded tap's click. Pinned by `numberInputModel.test.ts` (GESTURE), `e2e/numberFieldSwipe.spec.ts` |
| A field that saves on leaving also saves what was typed when the app goes away — without ending the edit | `NumberInput` saves a focused `'leave'` field on the window's `blur` or `visibilitychange` → hidden, by `numberCommit` (`awaySaves`), and leaves its text and `typed` alone. A new editor that saves only on leaving needs the same; the goal field and `SliderInput`'s edit box lack it (logged). Pinned by `numberInputModel.test.ts` (AWAY), `e2e/numberFieldAway.spec.ts` |
| Tab hidden guard | `useEffect` in `AppShell` redirects when the active tab is hidden, or is the CB Loan or Emergency tab with the Coinbase loan off. Full mode only; it re-runs on a switch of mode |
| `SettingsMain` ALL_TABS | Keep in sync with `AppShell` `ALL_TABS_META` |
| The venue colours: every venue mark reads a venue token, and a stored colour shows only if THE rule passes it (BL15) | Every venue mark — its dots, bar segments, chart lines and the limits drawn in its colour, its venue words and figures, the cold totals, the rows of the charts' shared hover box — reads `--venue-strike`, `--venue-coinbase` or `--venue-cold` (`tokens.css`), never their defaults `--text-primary`, `--coinbase`, `--btc` directly; only `tokens.css` reads `var(--coinbase)`. These keep their own colour: the bitcoin orange where it means bitcoin itself (Yours, BTC gained, ₿), the Cycling face's lone CB LTV line and its limit, the "Debt shifted" tile, the calendar's "CB collateral" dot, the hidden CB Loan tab's comparison columns. Every venue mark sits on THE rule's four surfaces — `--bg-app`, `--bg-card`, `--surface`, `--surface-2` — the shared hover box (`CyclingFace.module.css` `.tooltip`) included. The colours are a pref (`venueColors` on `prefs:v1`) whose undefined never travels; a stored colour reaches CSS only through `applyVenueColors` (`useVenueColors`, AppShell's first statement), and only if THE rule (`checkVenueColor`, `lib/venueColors`) passes it; the setter `setVenueColor` runs the same rule, starts from the colours the rule lets show, and writes nothing for the colour a venue already wears. Pinned by `venueColorsWiring.test.ts` (TOKENS ONLY, STAYS, SURFACES, ONE PAGE, SINK, PICKER), `venueColors.test.ts` (RESOLVE, SINK), `venueColorsStore.test.ts` (NEVER, HIDDEN, UNCHANGED) |
| The Almanac's faces: ONE catalogue, the grid (BL45), a list on a computer (BL46's A) | `almanacGrid.ts` alone decides which faces the hub offers, in which group and order (`FACE_TILES`, `faceShown`, `gridGroups` — pure: no store, no env). The hub reads its three gates once — `hasCbLoan`, `ledgerFaceAvailable` and the lens, `useSeenAsViewer()` — and passes them in (BL57 B4: no FIRE deploy gate; the hub reads no env), with no gate of its own; one fallback effect returns an open face whose gate closes to the grid. The owner's grid offers exactly the faces the pill row did; a trusted viewer's, those less the owner's-only FIRE (`ownerOnly`). A new face needs its tile, its `renderFace` branch above the Converter fallback and its `FaceIcon` drawing. Back is one level: on any face the header's "Almanac" (full mode: the eyebrow's) goes to the grid, with nothing between the header and the page; Branch I's edge swipe chains through `registerBack`, but a face the plan's link opened swipes straight out; the header's "←" always leaves, named for the page it opens. From 1200px (`ALMANAC_LIST`) the same groups are a list beside the open face — no grid page, so no step back: the header's "Almanac" is plain and the swipe leaves — and a face is always open (`firstListFace`: the one asked for, else the face last open this session while the list shows it, else Decision; in memory only, one memory per lens). 1200 is where every face keeps its own width beside the list in either mode: a wider list, or a face wider than 960px, moves it. Both sides of 1200 are one tree, so crossing it never remounts the open face. Pinned by `almanacGrid.test.ts` (CATALOGUE, ORDER, GATES, PILLS, GROUPS, GRID, ONE RULE, BACK, TITLE, BADGE, SHELL, ICONS, WIDTH, FIRST, LIST, KEEP, OWNER ONLY, NOTE, WHAT-IF), `e2e/almanacGrid.spec.ts`, `e2e/almanacList.spec.ts` |
| The simple-mode header's way out says where it goes, and never goes nowhere (BL47) | Branches H and I's "←" (Settings, the Almanac) reads `backPlace(to, { viewerMode, viewerPreview, simpleView })` (`Layout/backPlace.ts`, pure): the name of the page that tab opens, in AppShell's own order — "Almanac" (Branch I), a viewer's "Home" (Branch G), the owner's "Preview" (Branch J's preview), else "Dashboard" or "Journal" by `simpleView` (Daily and Monthly are both the Journal) — never a bare "← Back". The Almanac's way out (its "←", and its edge swipe from the grid) is `almanacExit(previousTab)`, never 'almanac'; Settings' keeps `previousTab`, 'almanac' included. Simple mode redirects no hidden tab. A new simple-mode branch, or a new page that opens Settings or the Almanac, updates the rule with its ORDER pin. Pinned by `backPlace.test.ts` (NAMES, VIEWER, PREVIEW, ALMANAC, EXIT, WIRED, EXIT WIRED, ORDER, GUARD), `e2e/backPlace.spec.ts` (DASH, JOURNAL, MONTH, NOWHERE, HIDDEN) |
| Trusted viewers in the Almanac (BL48 — BL40's second piece), and the owner's trusted preview of it (BL50) | The Almanac opens for the owner and a TRUSTED viewer only, by `Layout/viewerAccess.ts` (pure): `viewerTier` (trusted or safe by the last snapshot applied, none before one) and `almanacOpensFor`, which AppShell reads once. A trusted viewer's way in is his home bar's "Almanac" (`ViewerHomeView`'s `onOpenAlmanac`, passed only then; the edge-back under-layer's too). Any viewer's Settings and Almanac are simple mode's pages (Branches H and I take `viewerMode` as well as `simpleMode`), never the full-mode shell, whatever the owner's synced layout; the hidden-tab guard is the owner's full mode's alone (`if (simpleMode || viewerMode || …)`). A loaded viewer the Almanac doesn't open for (safe, or demoted) gets his home on the Almanac tab (Branch G) — one still waiting, the waiting gate first (in production; the dev server skips the gates) — and an effect puts `activeTab` and `previousTab` back to 'living'. In the hub, `ViewerWhatIf` (true) around the open face unlocks a viewer's shared inputs; FIRE's face puts the lock back (false). Everywhere else the lock stands: SliderInput, NumberInput and Toggle ask `useViewerLocked()` and read `viewerMode` no other way. A viewer gets no copies off the app (the schedule's Copy, Download and Print; the Ledger's CSV) and no Scenario Pin. The hub's viewer gates — FIRE's tile, the what-if note, Scenario's Pin row (its drift line and words too), the copies, the Ledger's Mining column — read the lens, `useSeenAsViewer()` (`Almanac/seenAsViewer.ts`): a viewer's device, or the owner's trusted preview — AppShell's one `PreviewAsViewer` provider, true around Branch I's hub while `previewTier` (`viewerAccess.ts`, pure) is 'trusted', false everywhere else. A face's data and its own lock still read `viewerMode` (GATES lists every reader). A new face control that SAVES locks for a viewer itself, or its face provides the lock back, and sits where the lens closes it (no `viewerMode` lock holds in the owner's preview). The hub's faces call only the store functions `viewerAlmanacWiring.test.ts`'s WRITES lists — two reads; the viewer's own tools, each named only in its tool's files (one, or two for `setBtcPrice`, `setMiningDevice` and `setMiningInputs`); three writes no viewer reaches, each named only in its own file (CALL SITES) — and a new one fails WRITES until it is decided. WAYS IN fails on a store module imported for anything but the hook or a type, `useStore` written other than `useStore(` or `useStore.getState().name`, `getState()` not followed by a name, and an inline arrow selector that returns or indexes its state. Both read source text only: a new face's store access is still the review's to read. Pinned by `viewerAccess.test.ts` (TIER, OPENS, ONE READ, HOME, PAGES, PUT BACK, PREVIEW TIER, PREVIEW WIRING, BAR), `seenAsViewer.test.tsx` (LENS), `viewerWhatIf.test.tsx` (LOCK, WHAT-IF, ONLY THERE, ONE READ), `viewerAlmanacWiring.test.ts` (WRITES, GATES, CALL SITES, WAYS IN, COPIES, PIN, NO WORD, PREVIEW), `almanacGrid.test.ts` (OWNER ONLY, NOTE, WHAT-IF), `backPlace.test.ts` (GUARD), `e2e/viewerAlmanac.spec.ts` (PARITY, PARITY LIST, WAY IN, SAFE, DEMOTE, COLD ZERO, FULL MODE, WHAT-IF, MINING, PREVIEW, PREVIEW BAR, PREVIEW HUB, PREVIEW SAVES NOTHING, PREVIEW WAY BACK, SAFE PREVIEW, FULL MODE PREVIEW) |

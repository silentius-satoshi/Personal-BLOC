# Rules — the journal: Daily, the month log, sign-offs and dollars

Read first, for what you touch: `docs/claude/daily-mode.md`, `docs/claude/journal.md`.

Each rule's full text — its mechanism, measures and history — is in `docs/claude/rules-in-full.md` § `journal.md`.

| Constraint | Rule |
|---|---|
| THIS MONTH, Daily and Daily's sheets print dollars to the cent (the plan of record, Run 2.1 — BL19) | Via `fmtUSDCents` (a crash step: the floored `fmtStepUsdCents`). The Almanac faces, full mode's own figures and the Dashboard keep their own formatters (among them `fmtUSD`'s whole dollars, the console's floored `fmtStepUsd`, the charts' `fmtTooltipUsd`). THIS MONTH's card prints cents wherever it shows (the full-mode Advisor tab too); THIS MONTH has no whole-dollar figure. A shared builder takes a formatter, whole by default — never a second copy of its words. Pins: planRunWiring's "no whole-dollar figure" test, the e2e's page scans |
| A draw/paydown with no `target` is STRIKE | Read the venue only through `flowVenue(ev)`, never bare `ev.target`. The `'strike'` default is the migration — any other default empties `expensesActual` across the whole plan. Pin: `cbDebtRollup.test.ts` |
| A Coinbase borrow/paydown is journal-only at EVERY dayLog reader | `rollupMonth` (it receives the FULL dayLog), `isMonthlyMeaningful`, `aggregateEvents`, the edit rebuild (`rebuildEditedFlow`) and the labels. A new consumer of draw/paydown must do the same. Never replace the rollup skip with "the filter upstream handles it" — `isMonthlyMeaningful` only gates whether a month re-rolls |
| A buy's dollars are the owner's | Typed or accepted on the sheet, stored to the cent, never re-priced by an edit. A dollars-only buy edit on a current entry writes only Income → BTC, never the full re-roll, so a signed month keeps its sign-off and every figure it recorded (`buyDollarsOnlyEdit`, `monthEntryCurrent`, `rerollMonth`'s `dollarsOnly`); an entry the lag check sees lagging, and every other edit, still re-roll and reopen. No dollars-only edit re-anchors the balances (current or lagging entry); every other edit does. A buy's dollars and a month's Income → BTC reach no engine, safety figure or sign-off. Pins: `buyDollarsStore.test` (SIGNOFF, KILL2), `eventSheet.test` (DOLLARS), `e2e/buyDollars.spec` |
| The journal's order — an edit, an Undo or a backfill never makes an older event the newest (Hotfix 1) | A day event's `ts` is the merge version clock: every edit and every Undo moves it. Order is `date`, then within the day `orderTs(e)` = `e.at ?? e.ts`; `at` is stamped by `updateDayEvent` (off the STORED copy, not the sheet's rebuild) and `undoDayEventDeletion`. Every "latest reading" and "after the anchor" reads (date, then `orderTs`): `deriveStrikeCollateral`, `deriveCbCollateral`, `rollupMonth`, `priorStocksForMonth`, `correctionDurability`, `unreconciledCbFlows`, the cold anchor, `deriveReadingAnchors`, the today sheet's prefill (`latestReadingForPrefill`) — "(date,ts)" in these rules means this. `ts` stays the version in the merge, the journal's pages and `monthEntryCurrent` — never `orderTs` there. An edited Strike move carries its own reading (`ownReadingAfterEdit`: same date, same place, states collateral) by the change, in whole sats; a delete or an Undo moves no reading. `at` is optional (absent = ts; no store bump); the backup checks it when present; a month's `strikeLtv` may be null (JSON's ∞). Pins: `journalOrder.test`, `journalOrderStore.test`, `validateJournalOrder.test` |
| An edit keeps a reading's Strike collateral as recorded (N1, BL39) | A reading that records a figure: the field shows it, editable and required; Save writes the field's figure — never today's total. A reading that records none (a past-dated add's, a balance saved from the Safety card or Quick Setup, any reading from before v20): none stays none — the field HIDDEN (never a blank 0) with a note, the gate waived, Save writes no `strikeCollateral` whatever the field holds. The field, its start and the gate read `readingCollateralPolicy`'s edit case, the Save `rebuildEditedReading`; never route a reading edit around either. The collateral track never runs on an edit (`if (isEdit) return`). To state Strike collateral for a reading that records none, log a reading for today. Pins: `eventSheet.test` (N1), `editedReadingStore.test`, `e2e/editedReading.spec` |
| Strike collateral (v20 Collateral-Truth) | Reading-anchored: `getCurrentBtcHeld() = deriveStrikeCollateral(dayLog, strikeCollateralBtc)` (the latest `strikeCollateral`-bearing `balanceReading` by (date,ts) + `target:'strike'` moves strictly after). `collateralAdjustment` is never written again (historical ledger — never "fix" the data). Buys never pledge unless the buy sheet emits an explicit `deposit target:'strike'`. A bare strike deposit with no `strikeCollateral` reading does NOT move current. `strikeCollateralBtc` is a LOCAL derived cache (rides partialize `...rest`, NEVER in `buildSettingsPayload`/`SETTINGS_FIELDS`; converges via the dayLog on records:v1). Monthly `btcHeld` is RECORDED from the month's reading by `rollupMonth`, OPTIONAL (absent = never recorded — never write 0), never recomputed. Never add it to `ROLLUP_NUM_KEYS` |
| `deriveCurrentPosition` | Signature `(monthlyLog, currentStrikeCollateral, baseBlocBalance)`; its `btcHeld` = the passed `currentStrikeCollateral` — callers pass `getCurrentBtcHeld()`, so `deriveCurrentPosition().btcHeld ≡ getCurrentBtcHeld()`. Standalone — no imports from runBLOC/runBlocYearOne. `blocBalance`/`lastLoggedMonth` come from the last logged entry |
| `MonthlyLogOverlay` | React portal to `document.body` (ToolsDropdown's pattern); centered modal (`.overlay` dim backdrop + `.modalCard`), header/arrows/dots inside the card; `initialMonth` 0-indexed; `openInEditMode` opens a logged month in the edit form. Its `months` (and `MonthlyLogSection`'s) are the plan of record's `PlanLogRow[]` (`planLogRows`) — never runAdvisor's rows |

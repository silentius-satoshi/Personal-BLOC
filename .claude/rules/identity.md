# Rules — keys, sign-in and sign-out, recovery and the backup ceremony

Read first, for what you touch: `docs/claude/access.md`, `docs/claude/recovery.md`, `docs/claude/nostr.md`.

Each rule's full text — its mechanism, measures and history — is in `docs/claude/rules-in-full.md` § `identity.md`.

| Constraint | Rule |
|---|---|
| Backup ceremony stamps once, self-waking | `RecoveryKeyCeremony` stamps via `setBackupVerifiedAt(Date.now(), nostr)` and NOTHING else — the setter's own plan event (`emitPlanSets` → `planDirty`) + `syncNow` wake un-gate sync. Never add a second dirty/publish at the call site. Besides `OwnerKeySetup` K2's pre-auth stamp, the ceremony is the ONLY verified stamp |
| NEVER collapse the sign-out dispatch to `external → reconnectNostr` | `signOut()` routes `nip07 → disconnectNostr` (the only teardown `useNostrAutoRestore` can't silently undo), `nip46 → reconnectNostr`, `local → signOutLocal`. Pins: `disconnect.test.ts` ("'nip07' → disconnectNostr, NOT reconnectNostr") |
| An identity-forget must never leave the plan blob readable | `disconnectNostr` (and "Remove local key", which delegates to it) calls `wipeLocalPlanData()` as its LAST mutation before `reload()` — no store setter after it. The wipe must remove `personal-bloc-onboarded`, not just `personal-bloc-store`. Never sweep by `personal-bloc-` prefix (`bloc-device-tag`, `bloc-nostr-log` lack it). Sign-out (`signOutLocal`, nip46 `reconnectNostr`) must NOT wipe. Pins: `disconnect.test.ts`, `wipeLocalPlanData.test.ts` |
| Sign out must NEVER clear `keyProvenance` / `backupVerifiedAt` (local) | `signOutLocal` (→ `reconnectNostr`) retains them, the identity and the wrapped key; only `disconnectNostr` and "Remove local key" clear them. The two exits must READ as different weights: "Sign out" neutral (`.signOutBtn`), "Remove local key" red (`.nostrDisconnectBtn`). Pins: `disconnect.test.ts` |
| ✅ FIXED (P0) — every unlock surface for a `scheme:'pin'` key MUST collect and forward the PIN | `restoreSigner(nostr, pin?)` forwards the pin to `unwrapSecretKey(wrapped, meta, pin)` (a PRF key ignores it). `LocalUnlockGate` and `NostrAuthGate.handleUnlockExisting` branch on `writerKeyWrapMeta?.scheme === 'pin'` and render a PIN `PassphraseInput`; any NEW unlock surface must do the same. `useNostrAutoRestore` skips `'local'`, so needs no pin |
| ⚠ The `restoreSigner` single-flight guard is PIN-AWARE — do not simplify it back | A pin-bearing call never joins a pinless in-flight restore; every other combination shares, incl. a pinless `syncNow` joining a pinned unlock. The PRF path never passes a pin, so PRF callers always share (WebAuthn's one-ceremony rule). The in-flight `.finally` keeps its ownership check (a superseded promise can't null its replacement's slot). Module scope holds only a `boolean`, never the pin. Pins: `restoreSignerSingleFlight.test.ts` |
| A bare nsec must save an encrypted backup BEFORE it establishes | `handleLocal`'s `nsec` branch captures the sk and returns; establishment happens only from the remediation step's Continue, gated on `bareNsecSaved`. The gate is on WHEN, not WHAT: a bare nsec still wraps `payloadKind: 'sk'`. `'encrypted'` and `'words'` skip remediation unchanged — never route them through it |
| A held key buffer is zeroed on success/teardown, NEVER in an establish `finally` | `establishLocalOwner` zeros its argument on success and failure, so always pass a `.slice()`; zero the long-lived buffer only on success, Back, scrub and unmount. Applies to `decryptState.sk` and `pendingSkRef`. Pins: `src/lib/__tests__/bufferAliasing.test.ts` |
| `nip49.encrypt` is ~1s of SYNCHRONOUS scrypt — yield before it | Every encrypt site (`RecoveryKeyCeremony.ensureArtifact`, `NostrAuthGate.buildEncryptedBackup`) does `setEncrypting(true)` → `await new Promise(r => setTimeout(r, 30))` → encrypt. A `prepRef` stale-guard is needed only where inputs stay live during the yield, not for a one-shot tap with `disabled={encrypting}` inputs |
| Reproducing onboarding-transition crashes | `npm run dev` reproduces `OnboardingModal`/`OwnerKeySetup` bugs but not auth/viewer-gate ones: every AppShell gate branch is suffixed `&& !import.meta.env.DEV` — neuter it only in scratch, never committed. In headless chromium `probeKeyVaultCapability()` returns `'pin'`, so mint→protect runs end-to-end without a passkey |
| No attestation checkbox on the IMPORT path | `localCanContinue` gates only on a valid RESOLVED key per tab (words checksum / nsec decode / ncryptsec decrypted) + a confirmed PIN when there's no passkey. Never add one to import |
| The ceremony verifies the artifact the user SAVED, not the one on screen | Verify branches on `verifyEncrypted` (`encryptOn` snapshotted at Continue in `goVerify`): PLAINTEXT → the word quiz / nsec last-6; ENCRYPTED → passphrase re-entry — never quiz the words there. `checkBackupPassphrase` trims both sides (the ceremony encrypts with `filePass.trim()`). The `setBackupVerifiedAt` stamp is byte-identical on both paths |
| No save, no Continue | `savedOnce` gates `Continue` in the reveal step; it is set by `doDownload` / `downloadQR` / a RESOLVED `share` (a share-sheet cancel rejects with `AbortError` and must not set it; guard `if (!navigator.share) return` FIRST — `await navigator.share?.()` resolves `undefined` and would set it). It resets inside `invalidateArtifact` |
| `RevealRecoveryKey` is view-only | It NEVER verifies or stamps `backupVerifiedAt` (the ceremony's job). Both branch on `payloadKind` (entropy → words, sk → nsec) via `unwrapRecoveryPayload`, never `unwrapSecretKey` |
| Ceremony idempotency | An already-stamped user MUST run explain→reveal→verify→done end-to-end as a re-verify — never a dead end; success re-stamps (monotonic-forward). The explain step shows a `Backed up ✓ <date>` chip but does not short-circuit |
| Import `payloadKind` is THREE-WAY asymmetric: **words → `'nip06-entropy'`, nsec → `'sk'`, ncryptsec → `'sk'`** | By construction: `NostrAuthGate.handleLocal`'s words branch passes `payloadKind: 'nip06-entropy'`; identity holds as `deriveSkFromEntropy(entropyFromWords(w)) === skFromWords(w)` (pins: `nip06Key.test.ts`, `establishOwner.test.ts`). nsec stays `'sk'` FOREVER, and ncryptsec likewise. No migration: an earlier words import keeps its `'sk'` ciphertext and nsec display |
| Never auto-strip a handoff token's `:npub` suffix | A pasted `<keyPart>:<ownerNpub>` in the Recovery-key tab is rejected, not repaired — its key is a `SharingPage` viewer key (`deriveViewerKeyFromNsec`). Detect by `.includes(':')`, not `parseHandoffToken(…) !== null`. Guarded in the render AND in `handleLocal` |
| Malformed payload ≠ wrong passphrase | `isWellFormedNcryptsec` gates whether the passphrase field appears at all; `classifyNcryptsecError` positive-tests `'invalid tag'` for the rest. Never collapse the two into one `catch`. Never render the caught `e.message` (bech32 echoes the whole ncryptsec into it) |
| The encrypted branch's payload MUST be `.slice()`d | `NostrAuthGate.handleLocal`'s encrypted branch reads its sk from React state (`decryptState.sk`) and passes `establishLocalOwner` a `.slice()`; nsec/words need no copy only because each attempt re-derives a fresh buffer. Never "optimize away" the copy. Pins: `src/lib/__tests__/bufferAliasing.test.ts` |
| The ceremony's save aids derive the sk from the STRINGS, never retained bytes | `RecoveryKeyCeremony` zeros the unwrapped payload the instant the display strings exist; its encrypt path re-derives via `skFromWords(words.join(' '))` / `nip19.decode(nsec).data` and zeros THAT buffer in a `finally` (pins: `nip06Key.test.ts`). Never retain `bytesRef` past reveal — that is `RevealRecoveryKey`'s exception (its on-open Advanced-nsec), not the ceremony's |
| Encrypt is a one-shot on tap; guard the stale result | The ceremony's 30ms yield leaves the toggle and passphrase field LIVE, so a monotonic `prepRef` token (plus `disabled={encrypting}`) discards a result whose inputs changed mid-flight. Do NOT debounce it like the decrypt |
| The QR PNG comes from `QRCodeCanvas`, not SVG rasterization | A hidden `display:none` `QRCodeCanvas` (`qrcode.react@4`) + `canvas.toBlob()` — no `XMLSerializer`, no `Image` load. It must pass `marginSize={4}` (the quiet zone); the on-screen `QRCodeSVG` may omit it only because `.qrPanel` pads it |
| Recovery grid is capture UX only | `recoveryGrid.ts` / `WordGrid` input mode / the checksum gate are HINTS; `skFromWords` on submit is the sole validity authority. Continue may gate on `phraseStatus==='valid'`, but a green box or ✓ line never authorizes anything the derivation wouldn't |
| `handleLocal` is one path | The Recovery-phrase / nsec tab only chooses the raw string fed to `classifyRecoveryInput` (words: `gridValues` joined; nsec: the field). From classification on — decode/`skFromWords` → `'imported'` stamp → `establishLocalOwner` → `sk.fill(0)` — one byte-identical sequence. Do not fork it per tab |
| `establishLocalOwner` derives its own sk | The signing sk is DERIVED from the payload it just wrapped (`payloadKind==='nip06-entropy' ? deriveSkFromEntropy(payload) : payload`), NEVER accepted from the caller. Never pass an sk alongside an entropy payload |
| `classifyRecoveryInput` | SHAPE only, never validity — `nip19.decode` and `skFromWords` own the verdicts |
| `remotePlanFound` | Session-transient (in `partializeState`'s omit list), never synced. `recordRemotePlanFound` is latched to fire once per session; `setRemotePlanFound(null)` (Dismiss) does NOT unlatch. Dismissal is per-session; the first edit ends it permanently |
| The `NoPlanNotice` mount | Owner-only by construction: `ViewerHomeView` renders `{ownerNav && notice}`; AppShell's dashboard arm is the only `notice=` call site. Never add a branch to AppShell's gate ternary, except F1's 'Loading your plan…', which ends with the first pull and offers 'Open the app' after 15 s |
| Backup ladder mutual exclusivity | The dashboard notice slot renders `<><NoPlanNotice /><BackupNagCard /></>`, exclusive by construction (`NoPlanNotice` gates `keyProvenance !== 'generated'`, the nag `=== 'generated'`); both self-gate and are owner-only. The nag also mounts standalone on both journal surfaces + the Settings menu (4 total) and fires pre-log (no data condition). All three rungs (badge/nag/interstitial) read `isBackupGateSatisfied` — never re-derive it — and self-clear reactively on `backupVerifiedAt`; no imperative cleanup. `backupNagDismissed` has NO module latch (resets each boot) |
| Ceremony has exactly TWO triggers | The nag's "Save it now" and RECOVERY's "Save your Recovery Key". The Identity & Security row stays NAVIGATION — never auto-open the ceremony from it when gated. `SettingsRow`'s `alert` prop is purely visual, never a behavior flag |
| `WrapMeta.payloadKind` | Absent ⇒ `'sk'` — the compatibility contract. Never make it required; never infer the kind from payload byte length. The unwrap branch tests `!== 'nip06-entropy'` (not `=== 'sk'`), so absent / `'sk'` / any unknown kind take the legacy path, and a wrapped key can never become unreadable |
| `unwrapSecretKey` return type | ALWAYS the 32-byte SECRET KEY, whatever the stored payload; its call sites must never be made payload-aware. To read the payload as stored, use `unwrapRecoveryPayload` |
| NIP-06 derivation constants | `m/44'/1237'/0'/0/0`, account 0, no BIP-39 passphrase, English wordlist. Never parameterize them in `nip06Key.ts`. A failing published-vector test is DATA LOSS, not a stale fixture |
| The words string | A transient secret: never persist/log it, put it in an Error message, or hold it in state outliving its screen. The zeroable forms are `entropy` (16B) and `sk` (32B); callers own zeroing both |
| Backup gate — no migration | `keyProvenance: null` = satisfied; grandfathering is STRUCTURAL (the persist `merge` fills the absent key from `current`). NEVER add a `migrateState` case for `keyProvenance`/`backupVerifiedAt`, and no store version bump |
| `setKeyProvenance` | WRITE-ONCE: a different non-null over a non-null is ignored + warns; the same value is a silent no-op. `null` is the explicit identity-teardown CLEAR (`disconnectNostr`, "Remove local key", `gateHydratedIdentity`'s signed-out branch); `reconnectNostr` + `resetAndResync` retain the identity and must NOT clear |
| Provenance stamp ordering | `setKeyProvenance(...)` is stamped BEFORE `establishLocalOwner`/`syncNow` at every establishment call site. The CALL SITES own the stamp — `establishLocalOwner` serves generated + imported and can't tell them apart |
| `setBackupVerifiedAt` | Authed: the emit's `set()` lands FIRST (field + plan event + `planDirty` + the debounced kick, whose publish waits for the first pull), then the wake via `syncNow` (dynamic-imported) — the gate must read satisfied inside `doSyncNow`'s guards. Pre-auth (onboarding's quiz-pass, before K3): the field ONLY, no event. No second wake mechanism. `null` = teardown clear (RAW — no event, no wake) |
| `backupVerifiedAt` latch | ONE-WAY LATCH by construction: no path emits a null `backupVerifiedAt` event (the teardown clear is RAW; the one emit sits after the null return), the fold writes only fields present in the log, and neither whitelist applier can write it (`hydratePrefs` takes `PREFS_FIELDS`; `applyViewerSettings` strips it) |
| Onboarding verifies by default (R2c-6a, SUPERSEDES the retired R2c-4a bridge) | `OwnerKeySetup` K2 stamps `backupVerifiedAt` only on a real verification — a save + a two-word quiz, NOT an ack; never gate the stamp on anything less. It is pre-auth field-only, before K3's `establishLocalOwner` `syncNow` wakes it. The skip path ("I'll do this later") stamps nothing → generated-UNVERIFIED → the ladder. `handleGenerate`/`handleStartOver` must `setBackupVerifiedAt(null)` on (re)mint. `backupGate.test.ts` drives the setters only; the K2 wiring is manual/tsc-covered |
| Seed-phrase hygiene copy — two variants, don't cross them | DISPLAY (`OwnerKeySetup` K2 + `RecoveryKeyCeremony` explain, one identical string): *"These words were generated fresh for this plan. Never use them as a Bitcoin wallet — same format, different job."* CAPTURE (`NostrAuthGate`'s word-grid tab only, never the nsec tab), BELOW the live checksum line: *"Never type your Bitcoin wallet's seed phrase here — a plan uses its own words."* |
| `disconnectNostr` | In `lib/nostr/disconnect.ts`. Clears all nostr state incl. `nostrPubkey` and `keyProvenance`/`backupVerifiedAt`, removes the standalone GATE_* keys synchronously via the setters, then `window.location.reload()`. Sign-out authority lives in the persist `merge`, never the racy blob: `gateHydratedIdentity` gates BOTH `nostrPubkey` AND `nostrSigningMethod` on the live `GATE_PUBKEY_KEY` + `GATE_METHOD_KEY` (GATE-first, blob fallback), and its signed-out branch (`!gatePubkey`) also nulls `keyProvenance`/`backupVerifiedAt`. In `merge` (every rehydrate), not `migrate` (version bumps only) |
| `resetAndResync` (escape hatch) | In `lib/store/escapeHatch.ts`; buttons in Settings + LocalUnlockGate. Reload-based and can NEVER erase relay data: `clearStoreEncryptionState()` (enc flag + pending-decrypt + on-disk `{ct,iv}` blob + in-memory key) → `window.location.reload()`; with the identity retained, the boot local-unlock's `syncNow` repopulates (no bespoke in-line pull). Imports NO publish symbol; the boot sync is dirty-gated. Returns void |
| `reconnectNostr` | In `lib/nostr/disconnect.ts`. Clears only the dead SESSION (`nostrSigner`/`nostrLogin`/`nostrBunkerUri`/`isAuthenticated`) and RETAINS the identity (`nostrPubkey` + `nostrSigningMethod`), so the auth gate (`nostrAuthEnabled && !nostrSigner`) reappears; clearing `nostrLogin` stops `restoreSigner` reviving the dead session. Both the bottom-right `⚠ Reconnect` affordance and Settings' "Reconnect" button call it |
| NIP-46 mobile login | Two-step manual launch — relay warms in foreground BEFORE the deep-link; auto-firing breaks the handshake |
| A wrapped key's derivation is part of the wrap's contract | What `keyVault.ts` derives a wrapping key from — `PBKDF2_ITERS` (`600_000`, `pinIkm`), PBKDF2's and HKDF's SHA-256, `HKDF_INFO`, `PRF_EVAL`, AES-GCM-256 — must open every key already stored: changing any of it takes a migration. Pin: `keyVaultHardening.test.ts` (HK-02), a stored PIN-path vector; the Face ID path is device-gated, untested |
